# ServeConnect — Web Dashboard Architecture & UI Component Catalogue (`serv_connect_dashboard`)

> **Scope:** Architectural baseline and `Serve*` Shared UI Component Catalogue for the **ServeConnect** administration and leadership console (`serv_connect_dashboard/`, React 19 + TypeScript 6 `strict` + Vite 8, npm, oxlint). Governed by [`serv_connect_dashboard/CLAUDE.md`](../serv_connect_dashboard/CLAUDE.md) and root [`CLAUDE.md`](../CLAUDE.md).

## 1. Architectural Overview & Module Boundaries

The web dashboard uses a **feature-first Clean Architecture** layout under `src/features/<feature>/`, backed by cross-cutting infrastructure in `src/core/`, typed REST transport in `src/network/`, and the shared `Serve*` UI Component Catalogue in `src/components/`.

```
serv_connect_dashboard/
├── .env.example                                 # Tracked VITE_* keys with placeholder values
├── scripts/i18n-codegen.mjs                     # Generates src/generated/locale_keys.g.ts + checks EN/AR parity
└── src/
    ├── main.tsx                                 # bootstrap(): AppEnvironment.assertConfigured() + root render
    ├── app/                                     # AppProviders, AppRouter, AppShell, AppSidebar, AppTopbar, RouteErrorBoundary
    ├── components/                              # Shared Serve* UI Component Catalogue (zero feature/API imports)
    │   ├── primitives/
    │   ├── shimmer/
    │   └── feedback/
    ├── core/                                    # Cross-cutting infrastructure (never imports features/)
    │   ├── config/                              # AppEnvironment, FeatureFlagService
    │   ├── event_bus/                           # AppEventBus, AuthEventBus
    │   ├── format/                              # AppFormatters (UTC ISO-8601, LocalDateString, orgTimeZone, Intl)
    │   ├── i18n/                                # i18next, LocaleController, OrgLabelResolver (useOrgLabels)
    │   ├── logger/                              # AppLogger (PII-redacting, no-op in prod)
    │   ├── permissions/                         # PermissionKeys, PermissionChecker, RequirePermission, ScopeGuard
    │   ├── session/                             # AuthSession (in-memory only), IdleLockWatcher, ConnectivityWatcher
    │   └── validation/                          # Centralised Zod Validation schemas, IdGenerator, assertNever
    ├── network/                                 # HttpClient, Interceptors, AppError, ApiResult<T>, Resources<T>, safeCall
    ├── styles/                                  # tokens.css (warm editorial palette) + global.css (logical RTL reset)
    ├── locales/{en,ar}/                         # common.json, nav.json, errors.json, validation.json
    ├── generated/locale_keys.g.ts               # Strongly-typed LocaleKeys generated by i18n:generate
    ├── features/<feature>/                      # Feature vertical slices (presentation, domain, data, index.ts)
    └── test/                                    # Vitest setup, MSW node server, renderWithProviders
```

### 1.1 Unidirectional Call Chain

`<Screen>Page` → `use<Screen>Controller` (`doAction` + `assertNever`) → `UseCase` / feature query hooks → `<Feature>RepositoryImpl` (`safeCall`) → feature API (`HttpClient`) + `<Feature>Mapper` (`DTO ↔ Domain Entity`).

- **Strict import boundaries:** `src/components/`, `src/core/`, and `src/network/` never import from `src/features/`. Cross-feature imports go exclusively through `src/features/<Y>/index.ts`.
- **Size & complexity discipline:** Every hand-written `.ts` / `.tsx` file is ≤ 250–300 lines, and every function, hook, or component body is ≤ 20–25 lines.

## 2. State, Result & Error Envelopes

### 2.1 `use<Screen>Controller` & Discriminated Union Actions

Every screen exposes a controller hook `use<Screen>Controller` returning `{ state: <Screen>State, doAction: (action: <Screen>Action) => void }`. All user intents flow through `doAction` using an exhaustive `switch (action.type)` terminated by `assertNever(action)`.

### 2.2 `ApiResult<T>` (`src/network/results.ts`)

Every repository and use-case method returns `ApiResult<T>`:
- `{ kind: 'success', data: T }`
- `{ kind: 'failure', error: AppError, message: string }`

Raw exceptions never escape `src/network/` or `data/` (`safeCall` converts all HTTP/network/parse failures into `ApiResult.failure`).

### 2.3 `Resources<T>` (`src/network/resources.ts`)

Presentation state envelope for async resources:
- `Resources.initial<T>()`
- `Resources.loading<T>(currentData?: T)` — preserves `currentData` during background refetches and pagination transitions so tables never flash back to a blank screen.
- `Resources.success<T>(data: T)`
- `Resources.failure<T>(error: AppError, message?: string, currentData?: T)`

### 2.4 Discriminated Union `AppError` (`src/network/errors.ts`)

`ErrorParser` maps backend `BaseApiResponse<T>` envelopes (`data`, `message`, `code`, `fieldErrors`) and network exceptions into `AppError`:
- `NetworkError`, `TimeoutError`, `ParseError`, `ServerError` (with `statusCode`, `code`, `fieldErrors`), `ForbiddenScopeError` (`403`), `FeatureDisabledError` (`403 ERR_FEATURE_DISABLED`), `ConflictError` (`409`), `NotFoundError` (`404`), `LoginRequired` (`401`), `UnknownError`.

## 3. Session, Token Refresh, Idle Lock & Safeguarding

1. **In-Memory `AuthSession` (`src/core/session/auth_session.ts`):**
   - `accessToken`, `userId`, `orgId`, `orgTimeZone`, and `RoleAssignment`s are held **exclusively in memory** — never in `localStorage`, `sessionStorage`, or `IndexedDB`.
   - Zero member/minor PII or Sensitive records are persisted to browser storage.
2. **Interceptors (`src/network/interceptors.ts` & `http_client.ts`):**
   - `AcceptLanguageInterceptor`: sends `Accept-Language: <ar|en>` on every request.
   - `AuthInterceptor`: attaches `Authorization: Bearer <accessToken>` on non-public routes and `Idempotency-Key` UUID v4 on mutations.
   - `RefreshMutexInterceptor`: serializes concurrent `401` responses onto a single shared `POST /api/v1/auth/refresh` promise. If refresh fails (`401`), it clears `AuthSession`, clears `QueryClient`, and emits `LOGIN_REQUIRED` on `AuthEventBus`.
3. **Wall-Clock Idle Session Lock (`src/core/session/idle_lock_watcher.ts`):**
   - Computes remaining inactivity time from wall-clock (`targetTimestampMs - Date.now()`). After `VITE_IDLE_TIMEOUT_MINUTES` of inactivity, locks `AuthSession`, clears `QueryClient`, and emits `IDLE_LOCK`.
4. **Permissions & Scope Gating (`src/core/permissions/`):**
   - Never branches on role names. Uses `PermissionChecker` (`hasAnyScope`, `hasPermission`), `<RequirePermission>`, and `<ScopeGuard>` combined with `FeatureFlagService`.
   - Receiving `403 ERR_FORBIDDEN_SCOPE` emits `SCOPE_REVOKED` on `AppEventBus`, purges cached queries, and displays a localized warning toast.
